Gemma 4 E2B
Model + Inference Runtime Comparison

ONNX Runtime and LiteRT-LM are evaluated through their WebGPU execution paths; llama.cpp is evaluated with Vulkan because it does not provide a WebGPU backend. This is an end-to-end comparison of converted artifacts, quantization formats, performance, quality, memory, and stack-specific optimizations. Measurements were collected on an NVIDIA RTX 4070 12 GB, Windows 11, driver 591.44 — 3 September 2026.

What models and artifacts were tested?

All runs target Gemma 4 E2B-IT, a 5.1B-total / approximately 2.3B-effective parameter model with 35 text layers, GQA, per-layer embeddings, and a 262,144-token vocabulary. These are separate conversions and quantization formats, so this evaluates complete model-plus-runtime stacks—not runtime code alone.

Model conversion and runtime optimization analysis

INT4 ONNX + ONNX Runtime GenAI

  • Multicomponent conversion: decoder, embedding, vision encoder, and audio encoder.
  • Decoder WebGPU graph capture enabled.
  • Mobius PR #479 prefill-prefix pruning is enabled and verified.
  • Decoder logits are [batch, 1, 262144].
  • All 35 split per-layer embeddings and the main embedding are block-quantized.
  • TTFT improves by 66.4–80.2% versus the previous unpruned artifact.
  • Past/present KV buffer sharing enabled.
  • No MTP drafter in this converted artifact.

INT4 LITERTLM + LiteRT-LM Native

  • Official Google AI Edge native litert-lm.dll, invoked through Python bindings.
  • Native WebGPU execution over D3D12.
  • Compact multimodal container with per-layer embedder and bundled MTP drafter.
  • Separate prefill-128, prefill-1024, decode, and verify signatures.
  • MTP run: 16,299 drafted, 6,087 verified; 37.3% acceptance.
  • MTP favors sustained predictable generation, not short turns.

Q4_K_M GGUF + llama.cpp

  • Text GGUF uses a different quantizer and package layout from ONNX/LiteRT.
  • Vulkan backend; all 35 layers offloaded to GPU.
  • Flash attention and optimized Q4_K_M kernels enabled.
  • draft-mtp needs a separate MTP-head GGUF; it was unavailable and upstream Gemma 4 issues remain open.

Comparison scope

This is a model-plus-runtime stack evaluation. ORT and LiteRT are direct WebGPU/D3D12 comparisons, but they use different converted artifacts. llama.cpp has no WebGPU backend, so Vulkan is the closest non-CUDA GPU path. Results must not be interpreted as controlled runtime-only kernel measurements.

Methodology and caveats

  • Five long-form prompts, three TTFT prompts, ten growing-context turns, and ten greedy quality checks were run per configuration after warmup.
  • Decode speed excludes prefill. LiteRT token counts are approximate; ORT and llama.cpp use runtime/tokenizer counts.
  • Timing boundaries differ: ORT/LiteRT TTFT includes first-token generation; llama.cpp reports prompt evaluation. Rankings are directional.
  • Model VRAM was already allocated before telemetry began. Peak totals are shown; peak-minus-baseline is not a comparable model footprint.
  • Sampling changes output length and content. One run per stack does not provide confidence intervals; use at least three repetitions and medians for release-grade claims.
  • The stacks use different container formats and quantizers. Results represent deployable stacks, not controlled kernel-only runtime performance.
